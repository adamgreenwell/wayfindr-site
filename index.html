Support without the shakedown.

The useful product should be the free product. Paid offerings should buy time, confidence, and operational calm, not unlock the real app.

Full product, not a teaser

The AGPL core is meant to be useful on its own: chat, visitor context, consent-based cobrowsing, ticket records, and audit trails.

Consent over creepiness

Cobrowsing should be requested clearly, scoped carefully, and designed around masked fields and visible user control.

Self-hosting that counts

If someone has the skill and time to run Wayfindr themselves, the project should respect that instead of booby-trapping the path.

The code is free. The help is paid. The project is sustainable.

What it does, and what it does not do yet.

Wayfindr is developed in the open. A feature you can install, a future plan, and a decision to defer something mean different things. Those states are marked here rather than blurred.

  • Shipped In a published release. Install it today.
  • In development Implemented work still awaiting its acceptance checks.
  • Planned Intended, deliberately unscheduled.
  • Deferred Decided against for now, on the record.

Conversations

  • Shipped Live chat through a script-tag widget, with visitor context and support codes
  • Shipped Email as a second channel, opening and continuing conversations
  • Shipped A help centre your visitors search from inside the widget
  • Shipped Support hours, an away state, and capture while you are closed
  • Shipped Replies emailed to a visitor who left an address while the desk was away
  • Shipped A pre-chat form with the fields you choose
  • Shipped Proactive messages, sent on rules rather than only in reply
  • Shipped Mailgun and Postmark pointed straight at inbound mail, with no proxy in front

Cobrowsing

  • Shipped Consent-based observe mode: requested clearly, scoped, and refusable
  • Shipped Masked fields and visible visitor control throughout the session
  • Shipped Sanitized page state, bounded diagnostics, and an inert replay preview
  • Planned Incremental DOM patching in replay, gated on a decision accepting the security tradeoff

Tickets and workflow

  • Shipped Assignment, statuses, priorities, categories, labels, notes and replies
  • Shipped Two-way links to GitHub, GitLab and Jira, with comment relay
  • Shipped Service level policies with breach warnings
  • Shipped Automatic assignment and routing
  • Shipped Automation rules and macros over a typed lifecycle
  • Shipped Bulk actions, a command palette, and global keyboard shortcuts

Visitors

  • Shipped Visitor profiles, safe host context, and reference trails
  • Shipped A directory of every visitor the desk has heard from
  • Shipped A live board of who is on the site now — off by default, disclosed to the visitor, declinable, and pruned within thirty days at most
  • Shipped Typed custom attributes, private contact notes, identity merge and export
  • Shipped Erasing a contact, or exporting everything held about them, when they ask — and erasures that survive a restore from backup

Measurement and alerts

  • Shipped Conversation and ticket volume, first response and resolution times, and who is carrying the queue
  • Shipped Satisfaction ratings, never reported over people who said nothing
  • Shipped Alert preferences, dashboard notifications and queued email digests
  • Shipped Background alerts, web push, quiet hours, and de-duplication across channels
  • Shipped A timezone per agent, so report day boundaries follow the reader

Accounts and access

  • Shipped Account roles, per-site access, and a separate platform-operator authority
  • Shipped Password recovery an agent can run without a production shell
  • Shipped Two-factor authentication with one-time recovery codes and an account-wide requirement
  • Shipped OpenID Connect single sign-on, custom roles, and role mapping that denies by default
  • Planned SAML, held until somebody actually needs it
  • Planned SCIM, which is a lifecycle decision rather than a login one

AI

  • Shipped An agent copilot: conversation summaries, reply drafts, suggested ticket details and knowledge snippets — every one a suggestion an agent edits or discards
  • Shipped Provider-neutral configuration, so an unset provider removes the feature instead of breaking the desk
  • Deferred An answer agent replying to your visitors unattended. The evaluation is done; the evidence was judged useful and insufficient

Running it yourself

  • Shipped Docker and Compose self-hosting, with guided first-run setup
  • Shipped An operator console for mail, storage, scanning, backups, language and region
  • Shipped Backup, restore, and an optional offsite mirror
  • Shipped Release manifests that state what an upgrade needs before it migrates or serves
  • Shipped Read-only release review in Operator → Updates, with deployment-specific guidance
  • Shipped Terminal upgrades that verify the target and preserve explicit recovery boundaries
  • Shipped Host helper 0.6.0 with Docker 29 support and separate, explicit administrator upgrades from published 0.4.0 and 0.5.0 helpers
  • In development Optional managed updates with reconnecting progress and host recovery — under disposable VM qualification, not yet qualified for production use
  • Shipped Break-glass support access: reasoned, time-bound, read-only, and audited
  • Shipped A read-only public API with a decided isolation model
  • Shipped Outbound webhooks and a narrow API write surface

Languages

  • Shipped A widget that picks the visitor's language: your page first, then their browser, then your default
  • Shipped English and German in the widget; English, German and Italian for agents
  • Shipped The operator console and most of the remaining dashboard translated
  • Planned A qualified speaker reading the German and Italian packs. The mechanical checks pass; that establishes nothing about whether a sentence is good German

Every release says what it needs from you.

Wayfindr is self-hosted, so the only question that matters at upgrade time is whether the upgrade is safe to take unattended. Every release answers that before it says anything else.

  1. 1.4.0 11 October 2026

    A corrected helper, with explicit replacement and recovery

    Host helper 0.6.0 supports separate upgrades from the published 0.4.0 and 0.5.0 helpers, corrects Docker process checks, and verifies the new helper is running and ready before completing replacement. Interrupted helper upgrades retain their original transaction for explicit recovery. A separate, narrowly scoped bridge preserves one supported failed application update during helper replacement; application recovery remains an explicit operator step.

    No operator action required for the application; pull and restart. This release adds no migrations. Application updates preserve the installed host helper. Choosing helper 0.6.0 requires a separate, explicit root-only helper upgrade from a reviewed public source distribution. Optional managed updates require separate enrollment and remain under disposable VM qualification, not yet qualified for production use. Published 1.2.0 and 1.4.0 provide a compatible source and newer target for those qualification runs. Read the helper upgrade procedure. Read the separate recovery bridge contract. Read the qualification boundary.

  2. 1.3.0 10 October 2026

    Docker 29 support, with a separate host helper upgrade

    Optional host helper 0.5.0 verifies release images on Docker 29 with either the classic or containerd image store, including the selected platform and image configuration. Enrolled hosts can replace the published 0.4.0 helper through an explicit upgrade that preserves enrollment and recovery state, with explicit recovery if the helper replacement is interrupted.

    No operator action required for the application; pull and restart. This release adds no migrations. Application updates preserve the installed host helper. Choosing helper 0.5.0 requires a separate, explicit root-only helper upgrade. Optional managed updates require separate enrollment and remain under disposable VM qualification, not yet qualified for production use. Published 1.2.0 and 1.3.0 now provide a compatible source and newer target for those qualification runs. Read the helper upgrade procedure. Read the qualification boundary.

  3. 1.2.0 9 October 2026

    Review an upgrade before it touches your installation

    Operator → Updates shows the running and proposed releases, required actions across skipped versions, prerequisites, backup policy and recovery limits. Docker, source and hosted installs receive guidance for their deployment owner. Terminal upgrades verify the target before activation and preserve recovery state when an outcome is uncertain.

    No operator action required; pull and restart. One additive audit-event migration runs automatically. Optional managed updates require separate enrollment and remain under disposable VM qualification, not yet qualified for production use. This is the first compatible source release; managed source-to-target qualification needs a later compatible published release too. Read the qualification boundary.

  4. 1.1.1 2 October 2026

    A clearer desk, easier to use on a phone

    The dashboard uses consistent type, spacing and pagination, with clearer visitor history, ticket context and grouped site settings. Phone ticket queues keep the essentials in view. Reports wrap long comments and open long charts on recent activity. Sign-in and recovery forms make help and errors clearer; keyboard tab choices survive a refresh, and removing a focused attachment returns you to Attach.

    Widget forms have readable editing text and roomier phone controls. No operator action required; pull and restart. This patch adds no migrations.

  5. 1.1.0 1 October 2026

    Forgotten when they ask, shown everything when they ask

    The two data requests a support desk meets most now have an answer on every contact's profile. Erasure removes everything Wayfindr holds about a person and keeps their tickets as work items with the personal content stripped out. Export downloads one archive of everything held about them. Both need a new permission, and both leave an audit entry that records how much, never what.

    Erasures also survive a restore from backup: an archive that brings an erased person back has them erased again before the desk serves anyone. No operator action required; pull and restart.

  6. 1.0.0 30 September 2026

    The version number makes a promise

    The application is the same as 0.11.0's. What changed is what the number tells you: from here, only a new major version can ask an operator to do anything beyond pulling and restarting. A minor adds features and migrates itself; a patch only fixes things.

    It also marks the bar the project set for itself: somebody who has never worked on Wayfindr installed it on a clean Ubuntu machine using only the public documentation, and it ran.

  7. 0.11.0 29 September 2026

    An account area for the person running it

    The people on an account got a Team page of their own, API tokens and webhooks became two tabs, and each integration folds its settings under its own row. Nothing about who may do what changed. A provider connection form that failed validation also stopped keeping its API token and webhook secret in the session.

  8. 0.10.0 28 September 2026

    Email replies that actually arrive

    Until this release, no agent reply to an email conversation was ever delivered, while the agent was told it had been sent. 0.10.0 fixed that, and sent every reply 0.9.0 had held back, threaded into the visitor's original email. A visitor who left an address while the desk was away now gets the reply by email too.

    Also in the release: a widget less than half the size, an account sidebar, phone-width dashboard pages that no longer scroll sideways, and a visitor's message that always reaches an agent who can be alerted.

  9. 0.9.0 24 September 2026

    A desk that can share the load

    Accounts gained two-factor sign-in, OpenID Connect, and custom roles. The desk gained service-level targets, automatic routing, automation rules and macros, bulk queue work, and a command palette. Agents can see disclosed, declinable live visitor presence, send bounded proactive invitations, receive Web Push alerts, and ask an optional copilot for suggestions they review before using. An AI that replies to visitors on its own remains deferred.

    Also in the release: direct Mailgun and Postmark inbound mail, outbound webhooks and narrow API writes, richer visitor contact records, per-agent timezones, and wider German and Italian dashboard coverage. Upgrading an existing host-managed PHP install requires checking its PHP and cURL requirements and acknowledging the release action. Wayfindr's image already includes those requirements; read the release notes for the exact steps before upgrading.

    Prepared as 0.8.0 and renumbered before it was tagged, so there is no 0.8.0.

  10. 0.7.0 25 August 2026

    Reachable by email, and measurable at last

    0.6.0 changed how Wayfindr looks; 0.7.0 changed what it can do. A desk that could only be reached through the chat widget can now be reached by email, answer questions before they are asked from a help centre inside the widget, and say when nobody is home. Reporting and satisfaction ratings arrived with it, so there is finally a way to know whether any of it is working.

    Also in the release: a pre-chat form, password recovery an agent can run without a shell, per-site widget appearance, a widget that speaks the visitor's language, a visitor directory, and a read-only public API.

  11. 0.6.0 21 August 2026

    The interface renovation

    The dashboard was rebuilt around a permanent sidebar, a colour per site, queues about four times denser, and a dark mode the widget follows too. Same application wearing a different face: data, URLs, and the install snippet on your pages are untouched.

  12. 0.5.0 18 August 2026

    Sites get a lifecycle

    A site can now be renamed, archived when you stop supporting it, or permanently deleted. Archiving destroys nothing and is reversible; deletion has to be archived first, done by an owner, and confirmed by typing the site's name.

  13. 0.4.0 14 August 2026

    Install anywhere, not just on a public domain

    localhost, bare IP addresses, and internal hostnames became supported install targets, with a certificate issued locally instead of an ACME challenge that could only fail.

    Followed by 0.4.1 – 0.4.4, which fixed the TLS handshake for installs at an IP address and moved the widget's last third-party dependency in-tree, so a self-hosted install now serves every byte it runs.

  14. 0.3.0 11 August 2026

    Advice that does not block the upgrade

    Releases can carry advisory notices — worth telling an operator, not worth stopping for — and they disappear on their own once the thing is done. Where the install genuinely cannot check, it says so rather than guessing.

    Followed by 0.3.1 and 0.3.2, which cleared Composer advisories and fixed a first-boot race on empty storage volumes.

  15. 0.2.0 10 August 2026

    The upgrade guard, exercised

    The first release you could upgrade to across a release boundary with a manifest on both sides. It deliberately demands nothing: the point was to prove the mechanism on a release where being wrong cost nothing.

  16. 0.1.0 5 August 2026

    The first stable release

    Mail, attachment storage, malware scanning and backups became things you configure in a browser rather than in a file, behind a guided first-run checklist. Backup and restore shipped with an optional offsite mirror, and a release learned how to state what an operator must do before it will migrate or serve.

    Preceded by the 0.1.0-alpha.1 – alpha.3 prereleases on 21 and 22 July 2026, the first Wayfindr builds published as installable artifacts.

After 1.0, the next thing is chosen by use.

Features marked Shipped above are in a published release. 1.0.0 was scoped and met in public; what follows it is picked from what real conversations show is missing, not from a parity list.

Met

1.0.0 — installed by somebody who did not build it

The bar for 1.0.0 was a person who had never worked on Wayfindr installing it from the public documentation alone. On 29 September somebody did, on a clean Ubuntu machine, and it ran. The account area was reorganised across 0.10.0 and 0.11.0 for the person administering their own install.

What was not observed is on the record too: nobody outside the project has yet been watched upgrading. Scripted clean installs and upgrades from 0.2.0 have run against each release from 0.9.0 through 1.1.1. Read what the install showed.

Next

After 1.4.0 — qualify the managed update path

Published 1.2.0 and 1.4.0 provide a compatible source and newer target, with helper 0.6.0 available through a separate administrator upgrade. Managed updates remain under disposable VM qualification, not yet qualified for production use. The qualification work covers enrollment, reboot behavior, application upgrades, failure and recovery across supported platforms and image stores, and independent restore on a second VM.

Ordinary installations keep their existing update path. Optional enrollment is separate from upgrading Wayfindr. Further product work stays demand-gated, and only a new major version can require more than pulling and restarting.

Deferred on purpose

An AI that answers your visitors

The evaluation work is finished: a harness that runs without a provider, a confidence and refusal policy, and sixteen synthetic cases run against several deployed models. The results ranged from every case passing to three missed, sometimes on the same route within the hour. The capability is still not being built.

Four synthetic runs inside ninety minutes establish nothing about drift, real adversarial or multilingual traffic, stale knowledge, or how it fails on somebody else's server. Until that evidence exists, the reply a customer reads belongs to a human. The decision is written down.

Further out, and deliberately unscheduled: single-page-app route tracking, richer host-app SDKs for WordPress, Laravel, Next.js and plain JavaScript, and broader automation surfaces. Parity work waits for a real operator to need it.

Past 1.0, in the open, and installable without its author.

Wayfindr is young — sixteen release milestones since August, with a seventeenth in preparation — but it is not a demo. You can self-host 1.4.0 today, and the support loop it was built around works end to end: install the widget, chat with a visitor, request cobrowsing consent, and turn the session into a ticket. Email, a searchable help centre, support hours, routing, automation, reporting, and a contact's right to be forgotten are in that release too.

Release review and terminal upgrade hardening are available, and 1.4.0 publishes host helper 0.6.0 with Docker 29 support and explicit replacement from published 0.4.0 and 0.5.0 helpers. Application updates preserve the installed helper; replacing it is a separate, explicit root-only upgrade. Optional managed updates remain under disposable VM qualification, not yet qualified for production use. Enrollment is not needed to keep using your existing update path.

From 1.0.0 the version number tells you whether an upgrade needs you: only a new major version can ask for more than a pull and a restart. One exception carries over from before it — a host-managed PHP install upgrading from earlier than 0.9.0 still owes that release's runtime check, and the upgrade guard will ask for it.
